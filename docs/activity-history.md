# 통합 실행 기록

## 목적

앱 셸의 `실행 기록` 화면은 트래커 작업공간의 단건 쓰기와 배치 작업의 최종 결과를 한 곳에서 확인합니다.
배치 화면의 행별 실시간 로그를 복제하지 않고, 나중에 작업 결과를 찾는 데 필요한 요약만 보관합니다.

## 기록 범위

| 구분 | 기록 시점 | 주요 정보 |
| --- | --- | --- |
| 단건 생성 | 성공 또는 요청 실패 | 프로젝트·트래커, 생성 아이템, 상위 아이템, 포함 필드 수 |
| 필드 수정 | 성공 또는 요청 실패 | 대상 아이템, 변경 필드 이름, 변경 전·후 version |
| 상태 필드 변경 | 성공 또는 요청 실패 | 대상 아이템, 이전 상태와 대상 상태 |
| 아이템 삭제 | 성공 또는 요청 실패 | 삭제 대상과 삭제 직전 version |
| 일괄 수정 | 청크 처리 완료·일부 실패·중단 | 대상·성공·직접 실패·롤백·미실행 건수, atomic 설정, 청크 크기, 요청 오류로 멈췄는지(`stopped_by_error`), 재시도용 실행 ID |
| Baseline Excel 내보내기 | 파일 저장 완료·실패 | 아이템 수, 선택 필드 수, 생성된 데이터 행 수 |
| 트래커 계층 Excel 내보내기 | 파일 저장 완료·실패 | 아이템 수, 선택 필드 수, 생성된 데이터 행 수 |
| 배치 작업 | 전체 완료·실패·사용자 중단 | 작업 모드, Dry Run 여부, 파일 수, 성공·실패·미해결 건수, 소요 시간 |

생성 API가 처리됐을 가능성은 있지만 생성 ID 또는 상세 재조회가 불완전한 경우에는 `일부 실패`로
기록해 단순 실패와 구분합니다. 조회, 검색, 상세 열기처럼 서버 상태를 바꾸지 않는 동작은 기록하지 않습니다.

## 저장 계약

- GUI 설정 폴더의 `activity_history.json`에 최신 순서로 저장합니다.
- 최대 500건을 유지하며 한도를 넘으면 가장 오래된 기록부터 제외합니다.
- 임시 파일을 먼저 쓴 뒤 교체하는 방식으로 저장 중 파일 손상 가능성을 줄입니다.
- 실행 기록 저장 실패는 이미 성공한 Codebeamer 작업을 실패로 바꾸지 않습니다.
- `기록 비우기`는 확인 대화상자를 통과한 경우에만 로컬 기록을 비웁니다.

## 보안 경계

실행 기록에는 다음 값을 저장하지 않습니다.

- Base URL, 사용자 이름, 비밀번호와 credential
- token, cookie, authorization, session 같은 민감 키의 값
- Codebeamer 원본 응답 JSON
- 배치 입력 파일명 목록과 행별 payload
- 일괄 수정에 입력한 실제 필드 값과 field payload
- Baseline 비교 필드 값, 원본 응답과 저장 파일 경로
- 트래커 계층 내보내기 필드 값, 원본 응답과 저장 파일 경로

세부 정보에 민감 키가 들어오더라도 값은 `***`로 마스킹하며, 긴 문자열과 큰 목록은 저장 전에 제한합니다.
배치 행별 오류 응답과 실시간 로그는 기존 `배치 작업` 화면에서만 확인합니다.

## 화면 사용

1. 좌측 앱 메뉴에서 `실행 기록`을 엽니다.
2. 작업 종류와 결과 상태를 선택하거나 ID·아이템·프로젝트·트래커·요약 검색어를 입력합니다.
3. 표의 기록을 선택해 아래에서 작업 컨텍스트와 안전한 세부 정보를 확인합니다.
4. 일괄 수정의 실패·롤백·미실행 대상이 있으면 해당 트래커를 선택하고 `실패 대상 재시도`를 누릅니다. 값은 저장하지 않으므로 다시 입력합니다.
5. 더 이상 보관할 필요가 없으면 `기록 비우기`를 누르고 확인합니다.

현재 화면은 로컬 결과 조회·일괄 수정 재시도·비우기를 지원합니다. 기록 내보내기와 Codebeamer 감사 이력 동기화는
아직 범위에 포함하지 않습니다.
